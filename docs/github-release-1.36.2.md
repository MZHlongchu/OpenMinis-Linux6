# Minis Ultra 1.36.2-linux

- versionCode **55**
- applicationId `com.openminis.linux`
- 启动器名称：**Minis Ultra**
- APK：`minis-ultra-com.openminis.linux.apk`（arm64-v8a）

## 本版摘要

针对共享中转 429（令牌桶按 **模型名** 分流、同一模型名在不同 key 上是不同桶）做了端到端修复：不再把「无可用渠道 / 额度不足」当可重试限流去空打；同桶排队、异桶并行；**只有会话选中「设置 → 模型组」时才会按组序换人**。只点了提供商下面某个模型时，失败也绝不会自动换到别的模型（避免不知情切到更贵的计价）。

## 变更

### 1. 429 分类：瞬时限流 vs 容量/额度

OpenAI / Anthropic / Gemini 的 HTTP 429 不再一律当成「等一会再试」。正文含无可用渠道、额度/余额不足、`model_not_found`、负载饱和等，映射为不可重试的容量错误，立刻走故障转移而不是 1/2/4/8/16 秒连打。普通限流仍带 Retry-After 和正文摘要，界面能看到真实原因。

### 2. 限流桶 = 中转 host + 密钥 + 模型名

同一中转、同一 key、同一模型名同时只允许一路 HTTP（标题/压缩/子代理不会把同一桶打爆）。不同模型名、或不同 key 上的同名模型，是不同桶，可以并行、可以互为备份。闸门可重入，避免 `sendMessage` 套 `streamMessage` 自己卡死。

### 3. 组内回退：只认设置里的模型组

- **回退 / 负载均衡**只决定会话先打组里谁；回合内换人规则相同。
- 网络错误 / 5xx：当前成员打完重试再换下一个。
- 普通 429 且组里还有别人：不在当前桶上空耗，立刻换下一个不同桶。
- 额度/无渠道：当前成员零次重试，直接换。
- 名单从当前成员下一位绕组一圈，每人一轮，不会无限循环。
- **未选模型组、只选了提供商列表里的某个模型：任何错误都不会按组序换模型。** 换模型只能用户自己点选择器。也不会因为「这个模型碰巧在某个组里」就悄悄启用组回退。

### 4. 设置 → 模型组

成员行显示限流桶（密钥指纹 + 模型名，不展示完整 key）。同一桶标红并提示 429 无法互为备份。页脚写明：只在会话选中本组时组内换人、绝不跳到其它分组、中转常按模型名计价请把便宜的放前面。

### 5. 其它防护

压缩遇到 429/额度错误不再把上下文劈成十几段去放大请求。子代理转不动不同桶时停止，不再打回同一把死 key。逐 token 的 RAW SSE 默认不再灌满 logcat，429 分类打到 `Minis.HTTP`。
