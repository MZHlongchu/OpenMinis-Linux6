# Minis Ultra 1.35.1-linux

- versionCode **52**
- applicationId `com.openminis.linux`
- 启动器名称：**Minis Ultra**
- APK：`minis-ultra-com.openminis.linux.apk`（arm64-v8a）

## 本版摘要

相对 **1.35-linux**：修掉「人格字数上限其实没去掉」的假修复；技能改为每次启动刷新并默认全量启用；多智能体并发上限/重试次数不再能手动输入；权限模式选「自动放行」后不再弹确认框。

## 变更

### 1. 人格字数上限真正移除（修 1.35 的假修复）

1.35 声称移除了长度限制，但 `SoulStore.isOverLimit()` 只加了一段说明注释，**原来的计数与判定逻辑仍在**——所以编辑器照样在超限时显示「已超出上限：N / M 字」。本版：

- `isOverLimit()` 直接返回通过，不再做任何字数判定。
- 设置页删除红色告警、上限文案与相关状态，只保留纯字数计数（如「58374 字」）。
- `minis-config` 写入与系统提示注入两条路径同样不再受长度影响，人格正文逐字全量注入。

### 2. 技能：每次启动刷新 + 默认全量启用

- 启动时（IO 线程，不阻塞首帧）重新扫描 `filesDir/minis-global/skills/`，磁盘上有但未登记的技能目录自动注册。
- **默认启用全部技能**；只有用户在技能页**手动关闭过**的技能保持关闭（关闭记录单独持久化，不会被启动刷新覆盖）。
- `SKILL.md` 的 frontmatter 缺失或格式不对时，按目录名兜底注册，不再静默跳过。
- 系统提示里可列出的技能数量上限由 20 提到 300——否则 100+ 个技能只有前 20 个会被模型看到。描述仍截断到 200 字符。

### 3. 多智能体：并发上限 / 重试次数

- 去掉「点击数字弹输入框」的手动输入方式，只保留 `-` / `+` 两个按钮。
- 当前值显示在行底部的副标题里（如「同一回合最多 4 个队友并行」）。

### 4. 权限模式：自动放行不再询问

根因：工具分类的兜底分支把未知工具判为「不可逆」，而 `ALLOW_ALL` 模式下旧代码对「危险 / 不可逆」操作仍然返回一次确认——于是 `file_write` 这类常规写入照样弹窗。现在 `ALLOW_ALL` 直接放行：

- 致命命令（`FATAL_BANNED`）仍在更早的分支被拒绝。
- 权威围栏、规则拒绝（`deny`）仍然生效——它们是显式拒绝，不是询问。
- `ASK` / `READ_ONLY` / `PLAN` / `DENY_ALL` 行为不变。

---

**未变更**：数据库版本（Room 14）、审批卡片与通知栏审批入口、本会话「全部允许」开关、协作角色自定义、人格扩展合并页。
